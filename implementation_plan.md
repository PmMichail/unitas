# План впровадження: Виправлення парсера PDF-виписок Монобанку (ФОП)

Виправити некоректне розпізнавання виписок Монобанку (ФОП), де ліцензійна інформація банку помилково розпізнавалася як транзакція, а реальні транзакції пропускалися. Буде реалізовано спеціалізований геометричний парсер на основі `pdfplumber` та аналізу середніх точок.

## Необхідне узгодження з користувачем

> [!IMPORTANT]
> Виправлення локалізовано в `backend/ai_parser/universal_parser.py`.
> Всі інші імпорти (Privat24, А-Банк тощо) залишаються сумісними та працюватимуть без змін.

## Пропоновані зміни

### Бекенд-парсер

#### [MODIFY] [universal_parser.py](file:///Users/mac/.gemini/antigravity-ide/scratch/unitas/backend/ai_parser/universal_parser.py)

- **Зміна маршрутизації PDF**:
  У методі `_parse_pdf` додати перевірку на ключові слова Монобанку/Універсал Банку (`"універсал"`, `"universal"`, `"монобанк"`, `"monobank"`). У разі їх наявності викликати новий метод `_parse_monobank_pdf(file_path)`.
- **Реалізація нового методу `_parse_monobank_pdf`**:
  - Завантажити PDF за допомогою `pdfplumber`.
  - Згрупувати слова по вертикалі в рядки з толерантністю `3.0` одиниць.
  - Нормалізувати українські літери `"і"` / `"І"` (латинські на кириличні в кириличному контексті) для правильної роботи регулярних виразів.
  - Розподілити слова по 5 колонках на основі координат `x0`:
    - `date`: `x0 < 70` (містить дату та час операції)
    - `details`: `70 <= x0 < 195` (містить опис платежу)
    - `contragent`: `195 <= x0 < 315` (містить назву, IBAN та ЄДРПОУ контрагента)
    - `amount`: `315 <= x0 < 365` (містить суму транзакції)
    - `balance`: `365 <= x0` (містить валюту та баланс, ігнорується)
  - Згрупувати рядки в межах транзакцій на основі вертикальних середніх точок між заголовками транзакцій (рядками з датою).
  - Провести очищення колонки контрагента: вилучити рядок `IBAN:`, рядок рахунку `UA...` та рядок `ЄДРПОУ: 12345678`, щоб витягти чисту назву контрагента.
  - Зберегти коди ЄДРПОУ та IBAN в окремі поля словника транзакції.
  - Відфільтрувати заголовки та підвали за допомогою геометричного обмеження: ігнорувати рядки вище `first_tx_top - 15` та нижче `last_tx_top + 70`.

1. Запустити інтеграційний тест на завантаженій виписці Монобанку:
   ```bash
   /Users/mac/.gemini/antigravity-ide/scratch/unitas/.venv/bin/python scratch/test_monobank_integration.py
   ```
2. Перевірити, що:
   - Розпізнано саме **2 транзакції** (Військовий збір на -250.00 грн та Еквайринг на +985.02 грн).
   - Ліцензійні рядки вгорі виписки відкинуті.
   - Обидва контрагенти розпізнані правильно: `"ГУК У ДН-КІЙ ОБЛ/ДН-КА ОБ/11011000"` та `"АТ "УНІВЕРСАЛ БАНК""`.
