# Інструкції для сніффінгу OAuth запиту ДПС

## Мета
Визначити точний формат запиту до шлюзу авторизації ДПС та текст, який підписується.

## Кроки

### 1. Відкрити Developer Tools
1. Відкрийте браузер (Chrome/Firefox)
2. Перейдіть на https://cabinet.tax.gov.ua
3. Натисніть F12 або Ctrl+Shift+I
4. Перейдіть на вкладку **Network**

### 2. Відфільтрувати запити
1. У полі фільтрації введіть: `oauth` або `token`
2. Або відфільтруйте за типом: `XHR`

### 3. Здійснити вхід з КЕП
1. Натисніть кнопку "Увійти з КЕП"
2. Виберіть ваш сертифікат (ЄДРПОУ 9883657)
3. Підпишіть запит

### 4. Знайти OAuth запит
1. У вкладці Network знайдіть POST запит до:
   - `/ws/auth/oauth/token`
   - або аналогічного ендпоінту авторизації

### 5. Переглянути деталі запиту
Натисніть на запит і перейдіть на вкладки:

#### Headers
- **Request URL**: повний URL ендпоінту
- **Request Method**: POST
- **Content-Type**: має бути `application/x-www-form-urlencoded`

#### Payload (Request Body)
Перегляньте тіло запиту - там будуть параметри форми:
```
grant_type=...
username=...
password=...
```

Зверніть увагу на:
- Назви полів (grant_type, username, password або інші)
- Значення полів

#### Preview/Response
Перегляньте відповідь сервера:
- Якщо успішно - повертається access_token
- Якщо помилка - повертається опис помилки

### 6. Визначити текст для підпису
Залежно від реалізації КЕП в браузері, текст для підпису може бути:
- Чистий ЄДРПОУ: `9883657`
- ЄДРПОУ з часовим штампом: `9883657|1719500000`
- Спеціальна JSON строка
- Інший формат

Перевірте в коді браузера або плагіні КЕП, який саме текст підписується.

## Очікуваний результат

### Запит
```
POST https://cabinet.tax.gov.ua/ws/auth/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=password&username=9883657&password=MIAGCSqGSIb3DQE...
```

### Відповідь (успішна)
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "expires_in": 3600
}
```

## Після сніффінгу

Після отримання інформації:
1. Оновіть файл `/backend/uapki/test_dps_full.py` з правильними параметрами
2. Якщо текст для підпису відрізняється від ЄДРПОУ - оновіть `test_sign.json`
3. Перебудуйте Docker контейнер і запустіть тест

## Додаткові перевірки

1. **Перевірте URL**: можливо ендпоінт відрізняється від `/ws/auth/oauth/token`
2. **Перевірте User-Agent**: ДПС може вимагати специфічний User-Agent
3. **Перевірте додаткові заголовки**: можливо потрібні додаткові headers
