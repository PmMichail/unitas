## 3. Оплата: клієнт ↔ компанія, з бонусом 10%

Це найскладніша бізнес-логіка з описаного, і наразі **відсутня майже повністю**.

Вимоги користувача:
- Якщо **клієнт сам** реєструється й платить за акаунт — платить повну ціну.
- Якщо **компанія** запрошує/реєструє клієнта і клієнт оплачує — компанія отримує **10% бонусом**.
- В акаунті клієнта повинно бути видно "оплачено компанією" якщо оплату ініціювала компанія.

| Компонент | Стан |
|---|---|
| Джерело оплати (хто ініціював: клієнт чи компанія) | ❌ немає поля `paid_by` / `initiated_by_company_id` в `Subscription`/`Payment` |
| Нарахування 10% бонусу компанії | ❌ немає жодної таблиці бонусів/балансу компанії |
| Позначка "сплачено компанією" в кабінеті клієнта | ❌ |
| Існуюча логіка 10% комісії UniTax з маркетплейс-ордера (`liqpay_callback`) | ✅ але це **інша** комісія (UniTax бере 10% з компанії), не бонус компанії від клієнта |

### Що потрібно зробити (Фаза 3)
1. Додати в `Subscription` (або `Payment`) поле `initiated_by` (`client` / `consulting_company`) і `consulting_company_id`.
2. Додати таблицю `ConsultingCompanyBonus` (company_id, source_payment_id, amount, status: `pending`/`credited`).
3. При успішній оплаті підписки клієнта, якщо `initiated_by == consulting_company`, нарахувати 10% від суми на баланс компанії (нове поле `bonus_balance` в `ConsultingCompany`).
4. В кабінеті клієнта (`/dashboard` або `/billing`) відобразити банер "Оплачено компанією [Назва]" якщо `initiated_by == consulting_company`.
5. В кабінеті компанії — розділ "Бонуси" з історією нарахувань і поточним балансом.

## 4. Email-запрошення не надходять

**Корінна причина**: на бекенді (`fly secrets list --app unitas`) **не налаштовані** змінні `SMTP_SERVER`, `SMTP_USER`, `SMTP_PASSWORD`. Код у `send_email_with_attachments` (`@/Users/mac/.gemini/antigravity-ide/scratch/unitas/backend/api/main.py:13390`) при відсутності SMTP намагається fallback на "System Gmail API" — але це також, ймовірно, не підключено (потребує окремого OAuth-flow).

### Що потрібно зробити (Фаза 0 — найшвидше, критично)
1. **Потрібні дані від користувача**: SMTP-креденшали (сервер, порт, логін, пароль застосунку) або Gmail OAuth. Без них листи технічно не можуть надсилатись.
2. Після отримання — виконати `fly secrets set SMTP_SERVER=... SMTP_USER=... SMTP_PASSWORD=... --app unitas`.
3. Перевірити реальну доставку через тестове запрошення.

## 5. Пріоритети виконання (рекомендований порядок)

1. **Фаза 0** — Email/SMTP (потрібні креденшали від користувача) — без цього запрошення бухгалтерів/клієнтів не працюють.
2. **Фаза 1** — Реальна оплата маркетплейс-замовлень (LiqPay) + єдине модальне вікно статусу клієнта на `/marketplace`.
3. **Фаза 2** — Спрощений юридично значущий підпис угод ("через дію": код підтвердження + фіксація метаданих) + сторінка розрахунків з бухгалтерами.
4. **Фаза 3** — Логіка "хто платить" + 10% бонус компанії + позначка "оплачено компанією" в кабінеті клієнта.
5. **Фаза 4 (опційно)** — Повноцінна інтеграція КЕП (Дія.Підпис/Вчасно), якщо потрібна юридична сила підпису вища за "через дію".
